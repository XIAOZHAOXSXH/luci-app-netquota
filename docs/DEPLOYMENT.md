# NetQuota 图形化部署与使用

当前开发版本 **0.6.0**。新安装默认 **HTTP，免域名、免证书**；HTTPS 为可选项。部署、证书配置、接管启停和账号管理均通过 LuCI 页面操作，无需客户使用 SSH。

## 从哪里进入

打开路由器 LuCI，进入 **服务 → NetQuota → 接管设置**。

本机管理入口：`http://192.168.8.1:8080/cgi-bin/luci/admin/services/netquota/deployment`。上传私钥时使用页面提供的 **HTTPS 管理入口**，避免通过 HTTP 传送私钥。

首次安装需要通过固件提供的软件包上传功能安装同一版本的两个包：先 `netquota_0.6.0_all.ipk`，再 `luci-app-netquota_0.6.0_all.ipk`。安装默认关闭接管，已有配置与账号不会因升级被清空。

## 第一步：选择访客 Wi-Fi

1. 在“接管设置”中选择要使用的 GL 原厂访客 Wi-Fi。
2. 上网出口默认推荐当前实际默认路由，支持识别有线 WAN、无线中继等。通常保留推荐项即可。
3. “认证协议”选择 **HTTP · 免证书（默认）**，“认证域名”留空即可。需要 HTTPS 时再配置证书；有域名证书时填写对应域名，插件会自动添加本地 DNS 解析。
4. 点击 **保存网络设置**。
5. 如果访客 Wi-Fi 尚未开启，点击 **开启所选访客 Wi-Fi**，或在 GL 原厂访客网络页面开启。同频无线在应用时可能短暂重连。

插件只列出原厂标记为 Guest、且连接到独立 guest 网络的 Wi-Fi；普通管理 Wi-Fi 不在接管列表中，不会被改名或修改密码。

**GL 的 2.4GHz 和 5GHz 访客 Wi-Fi 通常共用 `br-guest`。** 选择其中一个代表选择整个访客网络；其他访客频段若开启，也会要求 NetQuota 认证。

本机选择为 `GL-MT3000-9c4-5G-Guest`，访客网关 `192.168.9.1`。当前出口为无线中继 `apclix0`，不是早期配置中的 `eth0`。更换上网方式后，应重新检查推荐出口；首版不会擅自替换正在接管的出口。

## 第二步：HTTPS 证书（可选）

**使用 HTTP 时跳过本步骤，直接创建账号并启用接管。** HTTP 不会出现证书不受信任，但账号、密码和会话没有 TLS 传输保护，浏览器可能显示“不安全”。请只使用专用上网账号，勿复用管理密码或个人常用密码。

成功生成或上传证书后，插件自动选择 HTTPS；若仍希望使用 HTTP，可在“认证协议”中手动切回并保存。切换协议会撤销旧登录，终端需要重新认证，但账号与已用流量保留。已有证书不会因切回 HTTP 被删除。

从旧版升级时保留原有 HTTPS 设置，避免自动降级；可先在页面停止接管，再显式选择 HTTP 并保存。

### 本地试用

点击 **一键生成测试证书**。证书和私钥在路由器本地生成，不需要上传私钥。证书包含保存后的访客 IP 或认证域名。

可点击 **下载公共证书**；下载内容不包含私钥。重新生成前会确认，已信任旧证书的终端需要重新信任新证书。

**自动生成证书不等于客户端自动信任。** 手机或电脑首次访问自签证书时可能显示证书提示，需要在终端信任证书或确认浏览器提示；某些系统认证小窗口不能处理提示时，请用完整浏览器手动打开认证地址。插件无法绕过浏览器的证书验证。

### 正式客户部署

1. 在第一步填写证书对应的认证域名并保存。
2. 使用页面中的 **HTTPS 管理入口**。
3. 展开 **正式部署：上传已有证书**。
4. 选择 PEM 格式证书/完整证书链，以及对应的不带密码的 PEM 私钥。
5. 点击 **上传并校验证书**。

插件会检查证书格式、有效期、地址匹配和私钥匹配。文件检查通过仍不代表所有终端都信任签发者；客户无证书提示的体验需要终端信任的证书和完整链。本版本未集成 ACME 自动签发/续期。

证书最大 32KB，私钥最大 16KB。私钥仅保存在路由器受保护目录，不回传页面，也不提供下载。启用接管后，须先停止接管才能更换网络或证书。

## 第三步：创建账号并启用

1. 在 **账号管理** 创建上网账号，填写密码、月度流量额度和重置日。
2. 回到 **接管设置**，查看“检查并启用接管”。
3. 确保访客网络、出口、时间同步和加速检查通过。HTTP 不要求证书；仅 HTTPS 模式需要证书通过检查。
4. 点击 **启用接管 → 确认启用接管**。
5. 等待显示 **认证与配额已接管**。

在 GL 原厂界面关闭硬件和软件网络加速。插件检测并提示，不自动修改这些全局选项。原厂 chrony 必须完成时间同步；时间不可信时暂停新认证与自动结算，账本保留，网络保持守卫。

## 终端如何上网

1. 连接所选访客 Wi-Fi，使用原访客 Wi-Fi 密码。
2. 若系统未自动弹出认证，使用完整浏览器打开认证地址，或打开 HTTP 网页触发跳转。
3. 使用管理员在 NetQuota 创建的上网账号登录；它与 Wi-Fi 密码是两套凭证。
4. 登录后上网。多个终端可共用同一账号，上传＋下载从同一月度总额度扣除。
5. 用尽后停止上网，下个结算周期恢复。用尽后仍能打开认证页查看用量和自助修改密码。

默认 HTTP 地址：**`http://192.168.9.1:2050/`**。可选 HTTPS 地址为 `https://192.168.9.1:2051/`。地址以“接管设置”页面当前值为准，需在受控访客网络内访问。**“认证页预览”只是预览，不用于实际登录。**

## 全局流量计费倍率

进入 **结算设置 → 流量计费**，输入 **1.00–5.00** 之间的倍率（最多两位小数），也可点击快捷倍率，再点击 **保存计费倍率 → 确认并生效**。默认 1.00 倍，所有账号使用同一倍率，上传＋下载均参与扣减。

例如先以 1.00 倍使用 20 GB，再设为 1.20 倍并新增使用 10 GB：实际流量 30 GB，计费用量 32 GB。当前周期已扣减的用量不会因更换倍率而重算。重置日到来后，两套周期用量归零，倍率继续保留。

总览、账号管理和流量统计顶部并列显示“本周期实际总量”和“本周期计费总量”，汇总所有未删除账号各自的当前周期；搜索或筛选账号不会改变总量。两套总量分别读取原始账本与计费账本，不用实际总量乘当前倍率重新计算。它们不是整台路由器出口总量或历史累计。

账号列表的主用量、进度与剩余额度按计费用量显示，并附实际用量供管理员核对。访客门户只显示已用流量、剩余额度、进度等自助信息，已用值与后台计费用量一致，不展示倍率及实际用量对照；访客 API 同样不返回这些管理字段。倍率变更记录保存在路由器账本中，设置页显示最近五次。

该功能用于人工预留上游流量余量，不保证和上游账单完全一致；未经过受控账号的流量不会自动分摊。倍率不是整船出口总流量上限。

升级至 0.6.0 会将账本从 schema v1 迁移至 v2，并按 1.00 倍保留旧用量。旧版后端无法读取 v2 账本，降级需要恢复升级前备份，不能直接覆盖安装旧包。

## 状态和停止接管

| 提示 | 含义 |
|---|---|
| 服务运行中 | 后台与管理 API 已启动 |
| 访客网络未接管 | 访客仍按原厂规则普通上网，不计量、不要求 NetQuota 认证 |
| 接管守卫中 | 当前尚未安全就绪，受控访客暂停转发；查看上线检查 |
| 认证与配额已启用 / 已接管 | 接管已应用，终端需要认证并受账号额度约束 |

点击 **停止接管 → 确认停止接管**，访客恢复原厂普通上网。账号、用量、结算策略和证书均保留。仅关闭浏览器或离开管理页面不会停止计量。

卸载前也应先在页面停止接管，再通过固件软件包界面卸载。卸载清理本包自有规则和 DNS 映射，不删除账本与证书；升级保留配置。

## 亮暗主题

管理页跟随 LuCI 实际亮暗主题，兼容 Argon 的系统偏好和强制主题。独立访客页跟随终端系统偏好。升级后如显示旧界面，请按 Ctrl+F5 强制刷新。

## 已验证范围与限制

- 实机为 MT3000 / GL.iNet 4.11.0 / OpenWrt 21.02-SNAPSHOT / kernel 5.4.211，fw3 和 nftables-nojson 0.9.6 共存。MT6000 仍需验证其实际固件和无线链路。
- 自动接管只支持已识别的 GL 原厂 guest 配置；不支持的固件布局会停止并提示，不猜测管理接口。
- 原厂 Guest 的 DHCP、DNS、WAN 转发许可应存在；插件沿用这些配置，不替代原厂网络隔离。
- 受控 Guest 首版阻断 IPv6 转发，管理网络不受此规则影响。
- 默认每 5 秒保存计数。突然断电可能丢失最后一轮未落盘数据，不承诺计费级精度。
- 额度下调到已用量以下时立即耗尽；账本保留完整用量，内核恢复值饱和至新额度以兼容本机内核。
- 尚未完成 MT6000、全速吞吐、启用接管后的整机重启/断电及长期稳定性验收。
