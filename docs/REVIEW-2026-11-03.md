# NetQuota 0.3.0 代码审查与实机验证

2026-11-03。按用户最新要求停止调用 dsh，由 Codex 直接审查、修复和验证。保留用户暂存的 Git 提交，修订位于其后的工作区；没有重置历史或改写用户提交。

## 审查结论

已有实现包含可复用的 SQLite 账本、周期算法及 LuCI 页面结构，但网络配额、服务生命周期和前后端集成存在阻止交付的问题。采用针对性重写与修复，删除无法验证生产行为的旧测试，未整库回退。

| 问题 | 修正版行为 |
|---|---|
| 上传、下载各分配完整额度，多终端总量不符合账号总额度 | 每个账号当前周期只有一个 nft quota，所有终端和两个方向共用 |
| 方向 counter 在配额判断前，耗尽后的丢包尝试仍计费 | counter 在 quota 之后，账本记录通过配额检查的报文 |
| 将 HNAT 干扰误判为接口/MAC 匹配失效，取消 MAC 绑定 | 使用服务器观测的 IPv4+MAC；测试先建立无加速转发基线 |
| nft 输出省略默认 until，解析器不能读取真实输出 | 接受裸额度及 until，拒绝 over；兼容旧方向对象以保存可读计数 |
| RPC 参数使用 32 位或普通 JSON 编码精度不足 | 额度和 ID 使用 INT64 签名，响应保留安全整数精度；实测 50GB |
| 将 UCI cursor userdata 放入可序列化设置 | 只返回普通配置数据，RPC 可以正常编码 |
| LuCI 返回值、嵌套 DOM 数组、主题 header 样式、翻译函数遮蔽导致页面损坏 | 六页使用真实 DOM；修复 Argon 下操作、图标、弹窗、格式字符串和设置页 |
| 改额度时可能覆盖原有待生效重置日 | 编辑器读取待生效日期，重置日仍在下一周期生效 |
| nixio.signal 不支持该用法、权限参数不匹配、启动脚本执行位遗漏 | 使用 uloop；采用本机支持的权限参数；防火墙脚本明确 0755 |
| 停止与重启交错，旧进程可能在清理后重建规则 | 先守卫，旧进程只保存最终计数、不放行；等待其退出后再清理或启动 |
| CGI 状态码和 CSRF 请求头与原厂 uhttpd 行为不匹配 | 状态行附 reason phrase；HTTPS JSON 同时携带 CSRF；真实无 CSRF 请求返回 403 |
| 只检查系统时间看起来合理，不能证明同步 | 查询现有 chrony 同步状态；未可信同步时不新认证、不自动结算，保留守卫 |

## 实机与范围

设备为 GL.iNet MT3000 原厂 4.11.0，OpenWrt 21.02-SNAPSHOT，Linux 5.4.211，Lua 5.1、SQLite 3.33、nftables-nojson 0.9.6、fw3/iptables。受控网络计量用 nft，HTTP 捕获用包自有 iptables 链；无需在路由器部署 Python 或外部服务。

规格书及 HTML 原型作为需求和界面参考；具体接口、密码学、TLS、计量和防火墙方案依据实机能力调整。MT3000 的结果不等于 MT6000 已认证兼容。

网络测试仅用 `nqtbr0`、`nqtw0` 和四个网络命名空间。没有把这些接口接入管理 LAN、WAN 或 Wi-Fi；仅临时关闭运行时 HNAT，退出后恢复其配置对应状态。初始 IPv6 邻居发现超过一秒会令旧基线超时，测试已增加等待并在固定实验地址上使用 nodad；必须先证实 IPv6 可达，才能验收其被阻断。

## 交付边界

- 受控 Guest 网络首版阻断 IPv6 转发。账号总量为通过配额检查的 IP 流量上传+下载；触发阈值的报文可能被丢弃，故方向统计可能略低于额度，但耗尽标志和零剩余额度会保留。
- 默认每 5 秒轮询并保存计数。骤然断电可能丢失最后一轮尚未落盘的数据；不承诺零误差或计费级精度。
- 初次安装不自动启用接管。需先配置独立 Guest、实际出口、可信证书和客户端信任，关闭加速并确认 chrony 已同步。当前原厂 Guest Wi-Fi 未启用，未擅自修改。
- 已验证服务重启；不据此宣称受控网络在路由器全重启、突然断电或恶意加速配置下已完成验收。本次观察到关闭接管状态下设备重启后服务仍运行，未做启用接管的开机流量窗口测试。
- 尚需 MT6000 真机、实际无线终端、全速吞吐和长时间稳定性验证。上述项目未标记为通过。

安装、配置和维护参见 [部署说明](DEPLOYMENT.md)；旧错误配额结论的纠正见 [实测说明](compatibility/nft-quota-semantics-mt3000.md)。

最终设备状态：两个包均为 0.3.0，后台运行、数据库完整性正常、账号数为 0、`enabled=0`。HNAT 配置恢复为原来的 1，测试证书、临时凭证和临时数据库已清理。管理 LAN/WAN/Wi-Fi 未作配置修改。最终安装包摘要见 [SHA256SUMS](../dist/SHA256SUMS)。

## 后续修订：0.5.0 默认 HTTP 与可选 HTTPS

按用户要求，新安装使用 HTTP，无需证书。接管设置增加“认证协议”，生成或导入有效证书后自动选择 HTTPS；也可显式切回 HTTP，已有证书保留。旧版配置升级时保留 HTTPS，本机通过实际 LuCI 页面显式切换为 HTTP。

两种协议共用认证、账号和配额逻辑。HTTP 不依赖证书，仅监听认证 HTTP 端口；HTTPS 保留原有 TLS 监听和 HTTP 跳转。拦截到其他站点的 HTTP 请求先跳转至配置的认证地址，避免来源校验阻止登录。HTTP 和 HTTPS 使用不同 Cookie 名，保留 HttpOnly、SameSite、CSRF、来源检查和限流；仅 HTTPS 使用 Secure。切换协议会撤销旧门户和网络会话，账本、账号密码与完整用量保留。HTTP 页面明确说明没有传输加密。

列表、详情、编辑弹窗统一使用待生效日期说明，继承状态显示“下期起：继承系统默认日”。后台在当前周期已使用系统默认日时，不再因重复保存继承选项生成日期安排，并在该账号再次保存时清除冗余安排；真实的默认日变更和显式日期变更继续在下一周期生效。原有账号的配额、密码、用量与周期边界不因部署被改写。

新增领域回归验证带用量的额度保存不新增日期变更、不清空用量、不改变当前周期；真实默认日变更仍保留，默认日恢复后冗余安排可在保存时清除。572 项领域断言、门户/部署测试与 33 项 Python 检查通过。
