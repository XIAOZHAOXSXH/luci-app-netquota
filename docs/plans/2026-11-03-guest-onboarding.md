# GL 访客网络图形化部署 Implementation Plan

**Goal:** 客户只通过 NetQuota 页面选择原厂访客 Wi-Fi、配置证书、检查并启停接管；将本机 GL-MT3000-9c4-5G-Guest 实际纳入控制。

**Architecture:** 新增管理员专用 deployment 模块和“接管设置”LuCI 页。发现 GL 原厂 guest Wi-Fi、共享 bridge、实际默认路由出口；验证配置后保存，异步重启服务并回报结果。沿用当前独立门户、守卫与共享额度，不接管管理 LAN。不使用 dsh 或子代理。

**Tech Stack:** Lua 5.1 / UCI / ubus / nixio / OpenSSL / native LuCI JS。

## Tasks

1. 只读发现当前 guest、wan/wwan、证书及加速状态；选择原厂 guest 配置而不是任意接口。显示 2.4/5GHz 共用 guest 的范围。
2. 增加管理员 get/save/check/start/stop、启用既有 guest Wi-Fi、生成/导入证书、下载公共证书接口。严格限制输入、管理 ACL、文件大小、文件权限及并发；不返回私钥。
3. 门户支持可选域名与自动本地 DNS 映射。证书校验主机名/IP、到期时间、私钥匹配；测试证书明确不等于自动信任。
4. 页面呈现检测结果、选择 SSID/出口、证书按钮/文件上传、前置检查及启停状态。客户不需要编辑 UCI 或执行 SSH。
5. 增加配置/证书/路由/接口保护测试；真实浏览器走向导，导入/生成证书，启用指定 Guest，检查守卫、门户和真实出口。必要的无线终端验证由用户手机配合，不切换当前唯一管理 Wi-Fi 连接。
6. 更新包和部署说明，保留既有账号与账本，交付实际可访问的门户地址和 UI 路径。

## Constraints and acceptance

- 不自动更改硬件加速，读取并报告；用户已授权在原厂关闭。
- 不声称私网 IP 的自签证书可以自动被手机信任。正式部署允许上传可信域名证书和私钥，填写域名后自动配置本地解析。
- 配置缺失时按钮展示具体原因；失败保持守卫，不误显示已接管。取消接管解释为恢复原厂 Guest 普通上网，不删除账号/证书。
- 本机实际出口已变为无线中继 apclix0，必须自动识别；不得沿用旧 eth0。
