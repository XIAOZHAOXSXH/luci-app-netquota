# NetQuota 0.6.1 展示改进验证

## 变更与计量范围

总览、账号管理、流量统计并列显示全部未删除账号当前周期的实际总量和计费总量。账号主用量沿用计费账本，并增加实际用量副行。搜索与状态筛选仅影响列表，不缩小汇总范围。

合计直接累加 `total_bytes` 和 `billed_bytes`，不以当前倍率追溯换算；未修改倍率算法、配额断网、结算和数据库结构。从 0.6.0 升级不需要新的数据库迁移。

门户使用“已用流量”，其值继续采用已记账的计费用量。页面及访客接口移除实际计数与倍率，管理接口继续保留原有两套数据。

## 本机检查

- Python：40 项通过，Windows 跳过 3 项需要 POSIX shell 的维护脚本执行检查。
- JavaScript 语法和 `git diff --check` 通过。
- `node tests/test_usage_display.js`：生产 LuCI 渲染器使用实际 16.44 GB、计费 16.9 GB 等不同数据，确认主值、双合计、当前倍率变化不重算已记账总量、空状态与兼容回退。
- 提交前本地构建两个 0.6.1 IPK，发布元数据版本检查通过；远程 IPK/APK 构建与发布结果以对应 Release 的 Actions 和 `BUILDINFO.json` 为准，APK 设备运行仍未验收。
- 除保留的个性化 `/etc/config/netquota` 外，实机安装的 37 个业务文件 SHA256 均与本地 0.6.1 IPK 内容一致。

## 新接入 MT3000 实机

设备报告 GL.iNet GL-MT3000、OpenWrt 21.02-SNAPSHOT r15812+926-46b6ee7ffc、kernel 5.4.211。新测试环境原先没有 NetQuota 和完整 LuCI；补齐原固件依赖后安装两个 0.6.1 IPK。原厂 5GHz Guest 开启，加速关闭，插件通过管理页面保存无线中继出口并启用 HTTP 接管。

- 源码 Lua 套件：633 项 domain 检查、规则解析、HTTP/HTTPS 门户及部署校验均通过。最初依赖未齐时的失败不作为验收结果。
- 真实访客浏览器：通过路由器 guest bridge 上的临时 namespace 和透明测试代理访问实际 HTML/JS/CGI，登录、查询、退出及连接异常提示通过，`pageErrors: []`。代理没有模拟成功响应。
- 门户接口：`used_bytes` 采用计费账本；不返回 `upload_bytes`、`download_bytes`、`total_bytes`、`billed_bytes`、`traffic_multiplier_percent`。HTTP 和 HTTPS handler 测试均覆盖原有认证流程。
- 真实流量：测试账号临时设为全局 1.50 倍，通过访客链路下载数据；稳定快照实际 280,277 字节，计费 420,415 字节。门户 `used_bytes`、剩余额度与管理员同一账号数据一致。
- 三页汇总：均显示实际 280.28 KB、计费 420.42 KB；账号列表主值 420.42 KB，副行实际 280.28 KB。搜索无匹配账号、筛选在线状态不改变全局汇总。
- 亮/暗主题、390px 手机布局和七个管理页检查均通过，无脚本异常。门户只显示已用、剩余、进度等自助信息，没有倍率及实际用量对照。

流量生成期间做两次独立 RPC 读取会出现快照时间差，因此汇总对照在下载完成、计数稳定后执行；本次没有把刷新差异误判为计费问题。
